# Domain docs

This project uses a single-context layout.

Before exploring the codebase, read root `GLOSSARY.md` and
any relevant decisions in `docs/adr/`.

If these files are absent, proceed silently. Domain-modeling
creates them when terminology or decisions need recording.

Use domain terms as defined in `GLOSSARY.md`. Note meaningful
glossary gaps for domain-modeling.

If a proposal contradicts an ADR, identify that ADR and explain
why the decision should be reconsidered.
