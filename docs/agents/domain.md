# Domain docs

This project uses a single-context layout.

Before exploring the codebase, read root `GLOSSARY.md` and any relevant
decisions in `docs/adr/`. If a file is absent, proceed. Domain modeling
creates these files when terminology or decisions need recording.

Use the terms defined in `GLOSSARY.md` and flag meaningful gaps. If a
proposal contradicts an ADR, identify it and explain why to reconsider it.
