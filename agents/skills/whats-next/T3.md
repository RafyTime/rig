# T3 thread launch

Read the current tool schemas and environment instructions. Discover configured
providers, models, and options through the capability tool; keep transport details
out of the work menu.

Use `t3_thread_launch` for a top-level thread. A supplied message starts work;
preview the prompt in the coordinating conversation before sending it. Delegated
subagents are a different execution mechanism.

Use the launch tool's workspace strategy to create and bind any worktree. Honor
the requested base; otherwise independent work starts from the remote default
branch with `startFromOrigin: true`, or the local default when no remote exists.
Dependent unpublished work uses its required local base. Preview branch, base,
and strategy; the actual worktree path is allocated at launch. Use the root
strategy for the existing checkout when appropriate.

Use stable client request IDs for retry safety. Follow required post-launch
read/wait instructions, and report returned thread links verbatim. After a partial
failure, preserve successful launches and retry only failed requests whose outcome
is known, avoiding duplicate threads.
